# Wallet routing investigation — 2026-09-10

## Status

Repair prepared locally. Actual extension popup verification of the repair is pending user approval. Do not describe the original issue as conclusively resolved or this release as independently audited.

## Reproduced evidence

- On the published v7 site in the user's Chrome, the selector displayed Phantom but Backpack opened an Approve Solana Message prompt.
- The address embedded in the membership message differed from the account shown in the Backpack prompt. Both test prompts were denied; no signatures or transactions were approved.
- A full reload reproduced the issue. The deployed wallet module matched the locally built module byte-for-byte, excluding a stale-build explanation for that module.
- Read-only local inspection showed separate Phantom and Backpack injected objects and separate named Solana Wallet Standard registrations. Phantom also registers a Sui wallet, so matching only the wallet name is insufficient.
- The site client router logged `RSC prefetch setup error: TypeError: f is not a function` and navigation exceptions.
- A failed community/status request left the original page's Opening the community indicator visible.

The exact internal extension transport cause of the old cross-wallet signing prompt remains unproven. The repair replaces that integration boundary rather than asserting that the old namespace fallback was the sole cause.

## Repair

- Discover the exact named wallet through the official Wallet Standard registry, requiring Solana mainnet, connect, and signMessage capabilities. No injected-global fallback.
- Capture connect and signMessage features from the same registered wallet before asynchronous work. Pass the selected account explicitly to signing.
- Reject ambiguous registrations, missing capabilities, account changes, changed signed messages, and signatures that fail strict Ed25519 verification against the connected public key.
- Use the Wallet Standard signing contract rather than passing Phantom's encoding argument to every wallet implementation.
- Show the selected wallet name in the action and progress text. Freeze the community wallet/token fields while verifying and clear stale wallet errors on selection changes.
- Use normal anchor navigation instead of the broken client-router path across existing links.
- Replace indefinite loading after a failed status request with a retry button; bound API network requests to 25 seconds.

## Completed checks

- 29 unit/regression checks: existing token/signature rules plus exact named-wallet routing, Solana vs Sui discrimination, all three supported wallets, missing and duplicate providers, cancellations, account switching, provider feature replacement, and wrong-account/message signatures.
- 43 local community integration checks using disposable keys and a mock RPC: signatures, cross-topic access, stored threads/replies, privacy, moderation, suspension, zero holding, replay rejection and logout.
- Actual Community component in a temporary local browser harness: Phantom invokes only the simulated Phantom; Backpack invokes only Backpack; absent Solflare errors without invoking either. Cancellation restores the actionable form.
- Built production artifact running locally: Membership navigation and return to Community work; Phantom selection is reflected in the connect button; the button is disabled before consent; dialog visually fits the current Chrome window.
- Production artifact service failure and recovery: empty isolated local database returns controlled error and retry action; applying existing migrations and clicking retry restores the join gate and clears the error without a page refresh.
- Type checking, targeted lint, production build passed. No production schema change.

Temporary diagnostic/browser harness routes were removed from app/ before the production build. Their source is retained under tests/fixtures for repeatable local testing, not public deployment. API mock settings were restored after integration tests.
